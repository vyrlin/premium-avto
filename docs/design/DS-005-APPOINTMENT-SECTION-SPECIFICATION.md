# Premium Avto Design System

# DS-005 — Appointment Section Specification

**Version:** 1.0

**Status:** Approved

**Project Phase:** Product Modernization

---

# 1. Purpose

**Секция записи на обслуживание** является финальной конверсионной секцией главной страницы Premium Avto.

Это не просто справочный блок контактов.

Appointment Section завершает продуктовую историю страницы и переводит пользователя к конкретному действию:

- отправить заявку;
- позвонить;
- посмотреть контактные данные;
- найти сервис на карте;
- в будущем связаться через MAX.

---

# 2. Communication Goal

После предыдущих секций пользователь уже понимает:

- кто такой Premium Avto;
- почему сервису можно доверять;
- какие услуги предоставляются;
- как выглядит реальный сервис;
- какие преимущества получает клиент.

Appointment Section отвечает на финальный вопрос:

> **Как записаться на обслуживание?**

# 4. Desktop Behaviour

На десктопе основной сценарий — форма заявки.

Композиция:

- форма слева;
- контактная карточка справа;
- карта ниже.

Форма содержит обязательные поля:

- имя;
- телефон;
- email;
- марка и модель автомобиля;
- описание проблемы.

Email является обязательным, поскольку мастер может:

- ответить письмом;
- отправить рекомендации;
- отправить предварительный расчёт;
- отправить счёт или перечень запчастей.

---

# 5. Mobile Behaviour

На мобильной версии основной сценарий — быстрый звонок.

Главная кнопка использует ссылку `tel:`.

Вторичная кнопка:

> **Написать в MAX**

Пока MAX является нефункциональной заглушкой со статусом **«Скоро»**.

Форма остаётся доступной на мобильных устройствах и располагается ниже быстрых действий.

---

# 6. Form Behaviour

Утверждённое поведение формы:

- AJAX-отправка без перехода на отдельную страницу;
- клиентская и серверная валидация;
- обязательный email;
- блокировка повторной отправки;
- `disabled`-состояние кнопки во время запроса;
- вывод сообщений внутри секции;
- `aria-live` для сообщений;
- очистка формы только после успешной отправки;
- сохранение введённых данных после ошибки;
- контролируемые JSON-ответы PHP.

---

# 7. Contact Data

Актуальный email:

> **premiumc@bk.ru**

Он:

- отображается в контактной карточке;
- используется в `mailto:`;
- используется как получатель заявок;
- используется в `From` и `Return-Path` почтовой конфигурации проекта.

Пароли, SMTP-учётные данные и другие секреты не являются частью Design System.

Существующий `block4` продолжает использоваться для контактной информации.

В рамках Appointment Section не изменялись:

- PHP-классы ядра;

- архитектура маршрутизации.

# 9. Visual Style

Компонент продолжает утверждённый визуальный язык главной страницы.

Основные принципы:

- тёмный фон финальной секции;
- светлые карточки;
- фирменные красные акценты;
- спокойная премиальная композиция;
- форма как главный desktop CTA;
- прямоугольная кнопка с умеренным скруглением;
- адаптивная карта;
- отсутствие горизонтальной прокрутки.

---

# 10. Mail Delivery

## Production

- Реальная доставка зависит от почтовой конфигурации хостинга.
- Production-доставка должна проверяться отдельно после публикации.

## Local Development

- Локальная почта перехватывается Mailpit.
- Интерфейс Mailpit доступен на `http://127.0.0.1:8025`.
- Mailpit используется только для разработки.
- Тестовые письма не отправляются в реальный внешний ящик.
