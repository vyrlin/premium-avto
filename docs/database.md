# 1. Назначение

Данный документ описывает структуру базы данных legacy-системы Premium Avto.

В отличие от большинства CMS, система использует крайне небольшую базу данных.

На момент исследования подтверждено существование всего четырех рабочих таблиц.

Именно они обеспечивают работу всего сайта и административной панели.

---

# 2. Общая информация

## СУБД

Подтверждено использование:

```text
MySQL 8.0
```

Подключение осуществляется через собственный класс

```text
DB
```

из

```text
_core/_classes/classes.php
```

---

## Имя базы

```text
detalauto_pa
```

Настройки подключения находятся в

```php
_core/_config/config.php
```

Основные параметры:

```php
DB_SERVER

DB_NAME

DB_PORT

DB_USER

DB_PWD

DB_CHARSET
```

---

# 3. Общая структура БД

На момент анализа база данных содержит четыре таблицы.

```text
detalauto_pa

├── gallery
├── seo
├── texts
└── users
```

Других рабочих таблиц не обнаружено.

Таким образом практически вся CMS построена на четырех сущностях.

---

# 4. Архитектура данных

Вся структура базы может быть представлена следующей схемой.

```text
                users

                  │

                  ▼

          Авторизация



texts ─────► Landing ◄───── gallery

                  │

                  ▼

                 seo
```

Особенностью проекта является отсутствие сложных связей между таблицами.

Внешние ключи практически не используются.

Каждая таблица отвечает за отдельную подсистему сайта.

---

# 5. Используемые движки

Во время исследования подтверждены следующие типы таблиц.

| Таблица | Engine |
|---------|---------|
| gallery | MyISAM |
| seo | MyISAM |
| texts | MyISAM |
| users | InnoDB |

Это означает, что исторически проект развивался постепенно.

Контентные таблицы остались на MyISAM.

Таблица пользователей уже переведена на InnoDB.

---

# 6. Связь БД с системой

Все обращения к базе проходят только через класс

```text
DB
```

Типичная схема выглядит следующим образом.

```text
PAGE

↓

DB::select()

↓

MySQL

↓

Array

↓

PAGE::html()
```

Прямых SQL-запросов из шаблонов не обнаружено.

---

# 7. Основные принципы хранения данных

После анализа схемы можно сделать несколько выводов.

• Контент хранится в таблице `texts`.

• Галерея хранится отдельно.

• SEO хранится отдельно.

• Пользователи полностью изолированы от остальных данных.

Такое разделение значительно упрощает сопровождение проекта.

# 8. Таблица texts

## Назначение

Таблица содержит текстовое содержимое Landing Page.

Практически все информационные блоки главной страницы загружаются именно отсюда.

---

## Структура

| Поле | Тип | Назначение |
|------|-----|------------|
| id | INT | Первичный ключ |
| block | INT | Номер информационного блока |
| title | TINYTEXT | Заголовок |
| text | TEXT | Основной текст |
| image | TINYTEXT | Изображение |
| active | ENUM(0,1) | Публикация |

---

## Использование

Основной механизм загрузки:

```text
get_block()

↓

DB::select()

↓

texts

↓

landing.html
```

---

## Блоки

Во время анализа подтверждены следующие значения.

| block | Назначение |
|--------|------------|
| 1 | Почему мы |
| 2 | Услуги |
| 3 | Используется отдельно (галерея) |
| 4 | Контакты |
| 5 | О компании |
| 6 | Партнеры |

---

## Особенности

Вместо создания отдельных таблиц для каждого раздела используется поле

```text
block
```

Это значительно упрощает структуру базы данных.

# Итоги первой части

После анализа общей структуры БД можно сделать вывод, что база данных проекта намеренно сделана минималистичной.

Несмотря на небольшой размер, она полностью покрывает потребности сайта:

- хранение контента;
- хранение SEO;
- хранение фотографий;
- хранение пользователей.

Такое решение хорошо подходит для небольшого корпоративного сайта и позволяет безопасно модернизировать систему без изменения структуры данных.
