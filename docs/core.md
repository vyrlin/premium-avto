# 1. Назначение ядра

Каталог `_core` является ядром всей legacy-системы Premium Avto.

Практически вся бизнес-логика сайта сосредоточена именно здесь.

Ядро отвечает за:

- загрузку конфигурации;
- разбор URL;
- построение страницы;
- работу с шаблонами;
- подключение к базе данных;
- авторизацию пользователей;
- генерацию HTML-форм;
- фильтрацию входных данных;
- вывод сообщений;
- работу административной панели.

Публичная часть сайта практически не содержит собственной логики и использует классы и функции, расположенные в `_core`.

---

# 6. Класс PAGE

## Назначение

Класс `PAGE` является центральным компонентом системы.

Через него проходит весь процесс формирования HTML-страницы.

Практически любой HTTP-запрос в конечном итоге заканчивается вызовом методов этого класса.

---

## Ответственность класса

Класс отвечает за:

- определение текущей страницы;
- загрузку содержимого страницы;
- выбор шаблона;
- замену плейсхолдеров;
- формирование итогового HTML;
- передачу готового документа браузеру.

Вся публичная часть сайта строится через данный класс.

---

## Жизненный цикл страницы

После анализа исходного кода подтверждена следующая последовательность работы.

```text
HTTP Request
      │
      ▼
PAGE::init()
      │
      ▼
PAGE::getContent()
      │
      ▼
include(index.html)
      │
      ▼
PAGE::$content
      │
      ▼
PAGE::html()
      │
      ▼
landing.html
cabinet.html
print.html
      │
      ▼
HTML Browser
```

---

## PAGE::getContent()

Это основной метод загрузки содержимого страницы.

Его задача:

1. определить путь к странице;
2. найти соответствующий файл;
3. подключить его через `include`;
4. сохранить сформированный HTML во внутреннем буфере.

Метод использует данные, сформированные маршрутизатором (`$_PATH`).

Основные элементы:

```text
$_PATH['page']
$_PATH['path_string']
$_PATH['folder_string']
```

Если файл страницы отсутствует, используется стандартная страница `404`.

---

## PAGE::html()

После получения содержимого вызывается метод:

```php
PAGE::html()
```

Он выполняет следующие действия:

1. выбирает активный HTML-шаблон;
2. загружает шаблон из каталога:

```text
_core/_parser/templates/
```

3. заменяет специальные плейсхолдеры;
4. выводит готовый HTML.

---

## Шаблоны

Подтверждены три шаблона системы.

| Шаблон | Назначение |
|---------|------------|
| `landing.html` | публичный сайт |
| `cabinet.html` | административная часть |
| `print.html` | печатные формы |

Шаблон выбирается динамически.

---

## Система плейсхолдеров

Вместо полноценного шаблонизатора используется собственная система подстановки.

Примеры плейсхолдеров:

```text
{#_TITLE_#}

{#_CONTENT_#}

{#_SEO_#}

{#_BLOCK_1_#}

{#_BLOCK_2_#}

{#_BLOCK_3_#}

{#_BLOCK_4_#}

{#_BLOCK_5_#}

{#_BLOCK_6_#}
```

Замена выполняется обычным

```php
str_replace()
```

Такой подход делает систему простой и очень быстрой.

# 7. Класс DB

## Назначение

Класс `DB` является единственной точкой доступа к базе данных.

Все SQL-запросы проекта проходят через него.

Это значительно уменьшает связанность компонентов.

---

## Используемая технология

Подтверждено использование

```text
mysqli
```

Устаревший интерфейс `mysql_*` не используется.

Это существенно облегчает совместимость с современными версиями PHP.

---

## Основные методы

После анализа подтверждены методы:

```text
connect()

query()

select()

selectOne()

secure()

insert_id()

close()
```

Каждый метод отвечает за отдельную задачу.

---

### connect()

Создает соединение с MySQL.

Использует параметры из

```text
config.php
```

---

### query()

Выполняет произвольный SQL-запрос.

Используется там, где не требуется дополнительная обработка результата.

---

### select()

Основной метод получения данных.

Возвращает массив строк.

Большинство страниц сайта используют именно его.

---

### selectOne()

Возвращает одну запись.

Используется при получении:

- пользователя;
- SEO;
- отдельных блоков;
- настроек.

---

### secure()

Дополнительное экранирование данных перед SQL.

Используется совместно с

```text
secur()
```

из `funcs.php`.

Таким образом система имеет два уровня защиты:

```text
HTTP

↓

secur()

↓

DB::secure()

↓

SQL
```

---

## Архитектурный вывод

Наличие одного класса DB значительно упрощает будущую модернизацию.

Например:

переход на PDO

или

использование подготовленных выражений

потребует изменений только внутри этого класса.

Остальная система практически не изменится.

# 9. Form Framework

## Назначение

Legacy-система содержит собственный фреймворк построения HTML-форм.

Вместо ручной генерации HTML используется набор специализированных классов.

Это позволяет централизованно управлять отображением элементов формы и уменьшает количество повторяющегося кода.

Подтверждённые классы:

```text
Form

Input
├── InputText
├── InputPassword
├── InputEmail
├── InputDate
├── InputTime
├── InputCheckbox
├── InputRadio
├── InputHidden
├── InputTextarea
├── InputSelect
├── InputSelectMulti
├── InputFile
└── InputButton
```

---

## Архитектура

```text
Form
 │
 ├── создаёт форму
 │
 ├── содержит элементы Input
 │
 └── генерирует итоговый HTML

Input
 │
 ├── Text
 ├── Email
 ├── Password
 ├── Select
 ├── Checkbox
 ├── File
 └── ...
```

Каждый элемент формы представлен отдельным классом.

Такой подход соответствует объектно-ориентированной архитектуре и значительно упрощает создание административных интерфейсов.

---

## Практическое применение

Практически вся административная часть сайта использует данный механизм.

При добавлении новых настроек рекомендуется использовать существующие классы Form и Input, а не создавать HTML вручную.

Это позволит сохранить единый стиль интерфейса.

# 13. Руководство для разработчика

Данный раздел предназначен для быстрого поиска нужного места в системе.

Перед внесением изменений рекомендуется сначала определить компонент, который отвечает за требуемую функциональность.

---

## Изменить главную страницу

Если необходимо изменить содержимое главной страницы.

Искать:

```text
landing.html

↓

get_block()

↓

таблица texts
```

Не рекомендуется изменять HTML непосредственно в шаблоне, если информация хранится в базе данных.

---

## Добавить новый информационный блок

Потребуется изменить:

```text
landing.html

↓

get_block()

↓

таблица texts

↓

административная панель
```

---

## Изменить SEO

Искать:

```text
admin/seo

↓

таблица seo

↓

PAGE::html()
```

---

## Изменить фотографии

Искать:

```text
таблица gallery

↓

get_block()

↓

landing.html
```

---

## Изменить авторизацию

Основные компоненты:

```text
USER

↓

auth.php

↓

таблица users

↓

COOKIE_NAME
```

---

## Изменить маршрутизацию

Основные файлы:

```text
public_html/index.php

↓

path.php

↓

PAGE::getContent()
```

---

## Изменить шаблоны

Все шаблоны находятся в

```text
_core/_parser/templates/
```

Подтверждены:

```text
landing.html

cabinet.html

print.html
```

---

## Добавить SQL-запрос

Не рекомендуется выполнять SQL напрямую.

Использовать:

```php
DB::select()

DB::selectOne()

DB::query()
```

---

## Добавить новую форму

Использовать существующий Form Framework.

Не рекомендуется писать HTML вручную.

Использовать:

```text
Form

InputText

InputSelect

InputCheckbox

InputFile

...
```

---

## Добавить новую страницу

Рекомендуемый порядок.

```text
Создать каталог

↓

Создать index.html

↓

При необходимости добавить данные в БД

↓

Использовать существующий шаблон
```

---

# 14. Что нельзя менять без полного анализа

Перед модернизацией запрещается изменять следующие компоненты без предварительного исследования.

---

## PAGE

Это центральный класс системы.

Любые изменения могут повлиять на весь сайт.

---

## DB

Единственная точка доступа к базе данных.

Любое изменение требует проверки всего проекта.

---

## secur()

Используется практически во всём проекте.

Нельзя менять её интерфейс.

Если требуется новая логика —

лучше добавить новый режим обработки,

не ломая существующие.

---

## path.php

Формирует глобальный массив

```php
$_PATH
```

От него зависит вся маршрутизация.

---

## config.php

Содержит:

- настройки БД;
- Cookie;
- Email;
- глобальные сообщения.

Перед изменением необходимо проверить использование всех констант.

# 15. Technical Notes

Во время исследования были подтверждены следующие особенности проекта.

---

## Собственный PHP Framework

Проект не использует

- Laravel
- Symfony
- Yii
- WordPress

Вместо этого используется собственный небольшой framework.

---

## Собственный Template Engine

Вместо Twig или Blade используется система плейсхолдеров.

Например:

```text
{#_CONTENT_#}

{#_BLOCK_1_#}

{#_SEO_#}
```

---

## Собственная библиотека форм

Используется объектно-ориентированная генерация HTML.

---

## Централизованная работа с БД

Все SQL проходят через класс DB.

Это значительно упрощает модернизацию.

---

## Централизованная фильтрация данных

Практически весь пользовательский ввод проходит через

```text
secur()
```

Это один из наиболее важных компонентов проекта.

# 16. Technical Debt

Во время анализа были обнаружены технические проблемы legacy-системы.

Они не требуют немедленного исправления,

но должны быть устранены поэтапно.

| Приоритет | Проблема | План модернизации |
|-----------|----------|-------------------|
| 🔴 Высокий | Технический пароль `5_5` | Удалить после проверки авторизации |
| 🔴 Высокий | Использование MD5 для паролей | Перейти на `password_hash()` |
| 🔴 Высокий | `create_function()` | Заменить на анонимные функции PHP |
| 🟡 Средний | Короткие PHP-теги `<?` | Заменить на `<?php` |
| 🟡 Средний | Конфигурация и сообщения находятся в одном файле | Разделить после стабилизации проекта |
| 🟡 Средний | Жёстко заданные строки (`jobhelp.center`) | Удалить при обновлении интерфейса |
| 🟢 Низкий | Отсутствие namespace | Не критично для текущего этапа |
| 🟢 Низкий | Отсутствие автозагрузки классов | Рассмотреть при глубокой модернизации |

# Заключение

Исследование каталога `_core` позволяет сделать следующие выводы.

Несмотря на возраст проекта, ядро обладает достаточно продуманной архитектурой.

Ключевые достоинства:

- единая точка доступа к базе данных;
- единая маршрутизация;
- единая система авторизации;
- собственный шаблонизатор;
- собственная библиотека построения форм;
- централизованная фильтрация входных данных;
- низкая связанность основных компонентов.

Это делает возможной **поэтапную модернизацию без полного переписывания проекта**.

Именно такой подход рекомендуется использовать при дальнейшем развитии Premium Avto.
